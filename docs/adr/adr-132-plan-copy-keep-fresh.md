# ADR-132：计划副本保鲜 —— 真源一改，所有版本工作目录里的副本就同步

- **状态**：已采纳
- **日期**：2026-11-27
- **关联**：ZD-064、ADR-121（版本上下文归属 fail-closed）、ADR-127（归属在计划里，不在合并里）、ADR-110（版本计划双写）、ADR-056（版本是一等分支）、C1、C3、C4

## 背景

ADR-121 修好了「版本上下文里归属解析 fail closed」这个**机制**，并把计划文件
复制进版本工作目录（`<worktree>/.zelto/versions/<plan-id>.json`）。

但 ADR-121 修的是「副本**根本不存在**」这一个病灶。**复制**解决了「没有」，
没解决「复制之后就再也不动了」。

## 病灶（实测 nimrtc-v14，2026-11-27）

ADR-127 把 7 片的归属从 v1 改到 v3 之后，计划真源是对的：

```
根真源 plan-1795166129234：  v1=3  v2=1  v3=12  v4=3  v5=1
```

但 v5 版本工作目录里的那份**副本**还是改之前的：

```
v5 副本：                    v1=10 v2=1  v3=5   v4=3  v5=1
```

副本**没有任何保鲜机制** —— 它是建版那一刻复制进去的，
之后 `zelto plan patch` 改真源，它不动。

### 后果不是「多显示一点旧信息」，是**归属解析被污染**

`resolveSliceOwnership` 读的是**当前目录**下的 `.zelto/versions/`
（ADR-056 定的目录约定，解析器照它读是对的）。
在版本工作目录里跑 `zelto merge` 时，读到的就是那份陈旧副本：

```
切片 v1-ice-recovery
  根真源归属：v3   ← 规格自己写明归 v3（ADR-127 已修正）
  v5 副本归属：v1   ← 陈旧副本说的
```

于是「基点从哪个版本分支 tip 起」「该合到哪条分支」全按**错的归属**算 ——
追溯链说的和实际落点对不上。

### 这跟 ADR-110 缺陷四是同一个形状

「**声明与现实不一致**」。只不过那次不一致的是「CI 读的被跟踪副本」，
这次是「归属解析读的版本目录副本」。

根因也同一个：**副本没有保鲜机制**。

## 决策

**真源一改，就把副本同步到所有已存在的版本工作目录。**

### 一、为什么在「改计划」这一刻做，而不是「读计划」那一刻

- 读的那一刻同步 = 每个读点都要记得同步 = **漏一个就错一个**；
- 改的那一刻同步 = 一次写，所有副本同时跟上 = **不可能漏**。

### 二、为什么不反过来让版本目录里的副本成为真源

ADR-121 明确「计划文件是这一版的真源」。真源必须唯一：
同一个计划会同时存在于多个版本目录里（v3/v4/v5 各一份），
「谁是权威」会变成一个新问题。

### 三、为什么副本同步失败**不阻塞**修正

真源已落盘 —— 副本是**派生的**。缺了它会让后续 merge 停下，
但那可以在 merge 那一刻说清楚，不该在这里把整个修正拦死。

不过**必须说出来**（逐个点名哪个版本目录没跟上）——
否则就是「悄悄留了个坑」。

## 影响面

- 只动**副本**（`.zelto/version-worktrees/<label>/.zelto/versions/<plan-id>.json`），
  不动任何 git 分支、提交、tag。
- C1（状态只在文件）不破 —— 副本仍落在 `.zelto/` 内，与既有约定一致。
- C3（判定确定性）不破 —— 纯文件复制与内容比对，不调模型、不触网。
- C4（append-only 事件）不破 —— 副本同步**不是**一次「动作」，
  它是修正动作的派生效果；真正的动作事件仍是 `draft.revised`。
- C2（`core/` 零第三方依赖）不破 —— 新模块只用 Node 内置 `node:fs`/`node:path`。

## 不做（边界）

- **不把副本提升为真源**（见决策二）。
- **不在「读计划」那一刻顺手同步**（见决策一）。
- **不回填历史**：nimrtc-v14 的 v5 副本在这次同步后才会变新 ——
  那是 fix-forward，历史事件不改（append-only，C4）。
- **不动 ADR-110 的双写**（`.zelto/versions/` + 被跟踪的 `versions/`）——
  那条链由 `VersionStore.save` 保证，本 ADR 只管版本工作目录这一份副本。

## 验收标准

1. `zelto plan patch` 之后，所有已存在的版本工作目录里的计划副本与真源**逐字一致**；
2. 版本目录里**原本没有**计划文件时会被补上（ADR-121 的原始病灶）；
3. 副本同步失败时**不阻塞**修正，但**必须点名**哪个版本目录没跟上；
4. `--info` 预演**不写盘**，副本也不动（没发生就不记，C4）；
5. `tests/version-plan-copy.test.ts`（13 例）与
   `tests/zd064-plan-copy-refresh-e2e.test.ts`（3 例）全绿、
   `npm run lint` 通过。
