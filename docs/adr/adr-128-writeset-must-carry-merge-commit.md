# ADR-128 切片写集必须带「合并提交」作证据 —— 计划里的写集要对账，不能是名义值

- 状态：Proposed（机制已由 ZD-059 实测暴露，落地方式待人拍板）
- 日期：2026-11-26
- 关联：ADR-127（计划归属修正）、ADR-126（产物证据来自提交 trailer）、ADR-051（写集）、ADR-114（分支归属/产物证据）、C9（写集预约运行时强制）

## 背景

ADR-127 修计划时逐片核对「计划里的 `writes` 与合并时实际带进 `version/v3` 的文件」，
7 片**没有一片对得上**（实测表见 ADR-127「落地」一节）：

- `v1-ice-recovery` 计划写 `3` 条（`src/engine/**` 之类的宽口径），合并提交实际带进 `15` 个文件；
- `v1-macos-install-proof` 计划里的 `docs/api/public_headers.manifest` 在版本分支上**根本不存在**；
- `v1-install-tree-video-deps` / `v1-install-tree-module-closure` 计划里的
  `docs/api/engine_api.md` 在这两片的合并提交里**没被改过**。

这些写集是**当初填计划时的名义值**。没有任何机制在合并那一刻把它与
「这一片到底改了什么」对账 —— 计划里的写集因此只是一句「打算改」，而不是「改了什么」的证据。

## 问题

写集有两份真源，彼此不校验：

1. **计划里的写集**（`versions/<id>.json`，被跟踪、进走查与 CI）—— 名义值；
2. **合并时实际改动的文件集**（git 提交，`Merge slice <id>` 相对第一父的差集）—— 事实。

ZD-057（ADR-126）已经把「产物在哪」从状态文件迁到了提交 trailer；**写集**是同一形状的
第二个缺口：判断依据在计划里，事实在 git 里，没有人把它们对一遍。

写集不是展示字段 —— C9 规定写集预约**运行时强制**。计划写集偏离实际时：

- 审核的人看到的是错误边界（宽了会以为安全，窄了会漏掉真实改动）；
- 下一个切片的写集设计可能建立在错的「历史边界」上；
- 审计（`zelto audit`）只能看到 `.zelto/slices/` 的写集，而那份也在 `.gitignore` 里。

## 决策（提案）

**写集必带合并提交。** 切片发生合并（`zelto merge`）时，把「这一片的合并提交」写入
事件（`slice.merged` 的 payload 已可承载 `commit`），并由以下两处之一把它带进
**被跟踪**的地方：

1. **计划**：`plan patch --slice <id> --write ...` 时允许同时钉 `--merge-commit <sha>`（或从
   `slice.merged` 事件解析），写集就是该提交相对第一父的差集（去掉 `docs/`、`specs/` 由人决定是否保留）；
2. **痕迹**：若不想扩大计划的职责，则在 `.zelto/` 之外维持一个**被跟踪的**写集快照
   （例如 `versions/writesets/<slice>.json`），由 `merge` 写入。

无论选哪条，都要新增一个**确定性校验**（C3）：

```
zelto plan check-writesets <plan-id>
```

对每一片「已合并」的切片：取合并提交，算差集，与计划写集比较；
不一致就**列出差异并失败** —— 不自动改计划（改计划仍是人的治理动作，ADR-127）。

## 为什么不让 `merge` 自动改写集

- 写集是**人批准过的边界**（规格的一部分）；自动改把它变成「事后追认」——
  追溯链上「批准的是这个边界」这句话就消失了。
- ADR-121 已经明确：**计划态**与**盘上事实**分开呈现，自动回写字集是同一个反模式。

所以：`merge` 只负责**留下证据**（提交 hash），`plan patch` 负责**人确认后修正**，
`plan check-writesets` 负责**查出不一致**。

## 影响面

- 新增一个 CLI 子命令（`plan check-writesets`），不改现有事件类型（`slice.merged` 已有 `commit`）。
- 计划 schema 不一定要加字段 —— 追得快的话可以直接从事件流读合并提交。
- 不破 C1–C9。

## 未决项

1. **选 1 还是选 2**（计划带提交 hash vs 独立被跟踪的写集快照）？
2. 差集里**要不要包含** `docs/`、`specs/`？这两类文件在切片过程中必然被改，
   排除了它们又会在「文档切片」上失真。
3. 对**迁移前的历史切片**（如这 7 片）是否补做？ADR-127 已在计划里改正写集，
   但计划里没有合并提交字段 —— 要不要为历史补 `--merge-commit`（需要额外写事件，不能手改）？
