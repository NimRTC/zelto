# ADR-109：驾驶舱可对外可达（VPN 内网）＋ 手机端窄屏适配

**状态**：已采纳（2026-11-25）
**相关**：ADR-072（Web 驾驶舱：只读 + 签字）、ADR-084（驾驶舱可接管）、
ADR-086（驾驶舱装上油门）、ADR-018（签字不自动合并）、
ADR-093（前端脚本作为资源文件）、AGENTS.md 硬约束 C1–C9、负向清单「完整 GUI」
**相关缺陷**：无（这是**能力扩展**，不是缺陷修复）

---

## 背景

人提了一个需求：

> **有必要给 zelto 做个手机端吗？现在编程的 agent 都跑在台式机上，
> 有时周末在外边，有查看进度和重启切片开发的需求。**

核实结论（逐条查了代码，不是凭印象）：

| 需求 | 现状 | 缺口 |
|---|---|---|
| 查看进度 | ✅ 已有。`/api/slices` 带 `progressLine` / `progressAt` / `elapsedMs` / `elapsedIdleMs`（ADR-072 §6.2、ADR-086 §3） | 窄屏下挤成一团 |
| 重启切片开发 | ✅ 已有。`POST /api/slices/:id/run`（开跑）、`/resume`（续跑）（ADR-086） | 手机发过去会被 403 全灭 |

**「做手机端」这个形态本身是错的**：要的能力驾驶舱已经有了，
缺的是「手机连得上」与「窄屏能用」这两件事。

### 三个拦路石（核实过程）

**拦路石一：绑定地址写死回环。**

```ts
// src/adapters/web/server.ts
const DEFAULT_HOST = '127.0.0.1';   // ADR-072 §7：绑定面不可配置
```

手机走 VPN 连的是台式机的 VPN 网卡地址（100.x / 192.168.x），
**连不上只绑回环的端口**。且 `src/cli/commands/web.ts` 根本不传 `host`。

**拦路石二：Origin 校验会拒掉手机的每一个写操作。**

```ts
private checkOrigin(req: IncomingMessage): boolean {
  const origin = req.headers.origin;
  if (!origin) return true;
  return origin === this.url;        // this.url = http://127.0.0.1:4321
}
```

手机浏览器的 Origin 是 `http://192.168.x.x:4321` ≠ `this.url`
→ **所有 POST 被 403**。而「重启切片开发」恰恰全是 POST。

**拦路石三（最要紧）：token 机制的前提被打破。**

ADR-072 §3 写得很清楚：

> 第三方网页读不到本页内容（`Same-Origin-Policy` 拦读），所以拿不到 token
> —— **除非 CORS 放行，而本服务从不发 `Access-Control-Allow-Origin`**。

这句话里「拿不到 token」的**根因不是 CORS，而是「只有本机能访问这个端口」**。
一旦绑定面放开到 VPN 网段，**同一 VPN 下任何设备 `GET /` 就能读到
`window.__ZELTO_TOKEN__`**，然后替人签字。

> 这是 ADR-072 §3 修掉的同一个洞（ADR-010 §9 写「无 session/cookie 不构成 CSRF 缓解」，
> 是把因果说反了）。**扩大绑定面 == 重新打开那个洞** —— 除非补上第二道门。

### 人已经做出的决定

| 决策点 | 人的选择 |
|---|---|
| 范围 | 窄屏 CSS + 对外可达 + Origin 修法，全都要 |
| 通道 | **手机已有 VPN**，能访问台式机 |
| 第二道门 | **信任网络隔离**（不强制访问密钥） |
| 绑定默认值 | 保持 `127.0.0.1`，对外必须**显式** `--host` |
| 窄屏适配 | **全页面**自适应（表格转卡片、按钮加大、导航折叠） |

## 决策

### 决策一：Origin 校验改为比对 `Host` 头 —— 这是真正的同源判定

**现状的缺陷**：`origin === this.url` 是「Origin 等于我自己启动时的地址」。
这只在「浏览器访问的就是启动时那个地址」时成立 ——
一旦从别的地址访问（换个网卡、换个 hostname、经 VPN），同源请求会被误拒。

**同源的正确判据是 `Origin` 的 host 部分等于 `Host` 头的 host 部分**。
这是浏览器同源策略自己的定义（scheme + host + port），不是 zelto 的发明。

```
Origin: http://192.168.1.50:4321
Host:   192.168.1.50:4321
        ↑ 同一个 host:port → 同源 → 放行
```

**为什么这没有削弱 CSRF 防线**：

第三方网页发起的跨站 POST，它的 Origin 是**攻击者自己的域**
（如 `https://evil.example.com`），而 Host 头是**浏览器要访问的目标**
（`192.168.1.50:4321`）。两者永远不可能相等 —— 除非攻击者能让
受害者的浏览器把请求发到一个**恰好同源**的地址，那它就不是攻击者了。

> **关键点**：CSRF 的本质是「浏览器自动带上目标站的凭据」。
> Origin ≠ Host 意味着「请求来自另一个源」，
> 而浏览器**一定会**在跨站请求里带上真实 Origin（不能伪造）。

**实现要点**：

- 比对前先**规范化**：`Host` 可能是 `192.168.1.50:4321`，也可能是 `192.168.1.50`（默认端口）；
  `Origin` 必带 scheme。取 `Origin` 的 `host`（含端口）与 `Host` 头**原样**比对，
  再补一条「`Host` 无端口 且 Origin 端口为 80/443」的兼容。
- **`Host` 头本身可伪造**（客户端可以随便设）—— 所以这条不能单独当凭据用。
  它是**同源判据**，不是**授权判据**。
  **授权仍然由 token 承担**（决策二）。
- `Origin` 为空（`curl` / 脚本 / 同源导航）→ 仍放行（ADR-072 原有行为，不变）。
- `Origin` 存在但**解析不出来** → **拒绝**（fail closed），不许「解析失败就当没有 Origin」。

### 决策二：token 仍是唯一授权凭据 —— 绑定面放开的代价，说清楚

**事实**：扩大绑定面后，**token 不再是「只有本机能拿到」的秘密** ——
它变成「任何能访问这个端口的设备都能拿到」。

**本 ADR 的立场**：这**可以接受**，前提是**绑定面必须显式开启**
（决策三），且**接受者必须知道自己在放弃什么**。

所以：

1. **默认仍是 `127.0.0.1`**。对外可达必须显式 `--host 0.0.0.0`。
2. **`--host` 非回环时，启动横幅必须明确说这句话**：

   ```
   🌐 zelto 驾驶舱已启动：http://0.0.0.0:4321
      ⚠️ 绑定面已放开：同一网络内的任何设备都能访问这个驾驶舱，
         拿到会话 token 后可以替你签字、拉闸、开跑。
         请确认你信任这个网络（VPN / 内网）。
   ```

   **理由**：不能让人在不知情的状态下把签字权开放出去。
   「默认安全 + 显式放开 + 放开时告知代价」—— 三条一起才是完整的决定。

3. **不做访问密钥**（人已明确选择信任网络隔离）。
   但**把这条写进 ADR**：将来若有人报告「同网段有人替我签了字」，
   本 ADR §决策二 就是已知的、被接受的取舍，**不是缺陷**。

> **诚实说明这份风险**：驾驶舱持有项目目录的**写权限**，
> 它能签字、能拉闸、能开跑 agent（烧 token）。
> 信任网络隔离 = 相信 VPN 里的其它设备不会恶意访问这个端口。
> 这是**人的判断**，工具不替他做。

### 决策三：绑定面默认 `127.0.0.1`，`--host` 显式放开

```
zelto web                     # 默认只绑 127.0.0.1（行为不变）
zelto web --host 0.0.0.0      # 显式放开（同一 VPN / 内网可达）
zelto web --host 192.168.1.50 # 只绑一张网卡
```

**为什么默认不放开**：ADR-072 §7「绑定面不可配置」的那条纪律，
**在「多了一个 CLI 参数」之后仍然成立** —— 变的不是「能不能配」，
而是「配了要**显式配**，且**配了会告知代价**」。

> **注意 ADR-072 §7 原文**：「绑定：**硬编码** `127.0.0.1`，**不可配置**」。
> 本 ADR **取代这一条**，理由是「手机端」这个真实需求（背景节），
> 且本 ADR 补上了 ADR-072 当时**没有**考虑的东西：
> 扩大绑定面后 token 前提被打破（决策二）。

**回环判定**：`127.0.0.1` / `::1` / `localhost` 视为回环（不需要警示横幅）；
其余（含 `0.0.0.0`）视为非回环（要警示横幅）。

### 决策四：窄屏适配 —— 表格转卡片，不用框架

驾驶舱现有 13 处 `table()` 调用，列数从 2 到 9 不等。
手机上 `max-width: 1200px` + 宽表格 = 横向滚动到底都看不到关键列。

**做法**（纯 CSS，零依赖）：

| 元素 | 宽屏 | 窄屏（`@media (max-width: 720px)`） |
|---|---|---|
| 表格 | `display: table` | `display: block`；每个 `tr` 变成一张卡片 |
| `th` | 表头行 | `display: none`（表头藏进每个单元格的 `::before`） |
| `td` | 单元格 | 块级，`::before` 显示「列名：」 |
| 导航 | 横向排开 | `flex-wrap: wrap`（按钮换行，不再横向溢出） |
| 按钮 | `padding: 6px 14px` | `padding: 11px 16px`（触摸目标 ≥ 44px 高） |
| 导航按钮 | `padding: 4px 12px` | `padding: 11px 12px`（触摸目标 ≥ 44px 高） |
| `.kv` | `grid-template-columns: 130px 1fr` | 单列（标签在上、值在下） |
| `main` | `max-width: 1200px` | `padding: 12px`（省横向空间） |

> **内边距是按实测倒推的，不是拍脑袋**：
> 13px 等宽字的内容高约 22.8px（行高 1.6 + 2px 边框），
> 上下各 11px 内边距 → **44.8px**。
> 最初写的是 10px（实测 42.8px）—— **差 1.2px 就是不达标**，
> 所以这里改到 11px 并在测试里把阈值钉死。

**为什么用 CSS 而不是「渲染两套 DOM」**：

`table()` 助手是**唯一的**表格构造入口（`src/adapters/web/frontend/app.js:139`），
所有表格都由它生成 —— 所以**一个 `@media` 断点就能覆盖全部 13 处**。
渲染两套 DOM 会让「桌面版与手机版内容不一致」成为可能（改了一处忘了另一处），
而 CSS 断点是**同一份 DOM 的两种排版** —— 内容永远一致。

> **实现要点**：`<td>` 里的 `::before` 要显示**列名**，
> 而列名现在只在 `<th>` 里。做法是在 `table()` 助手里给每个 `td` 加
> `data-label` 属性（值取对应 `headers[i]`）—— 这是**数据属性**，
> 不改可见结构、不改 API 契约、不改事件流契约。

### 决策五：不做 App、不做公网服务

- **不做手机 App / PWA**：驾驶舱是**开发工具的观察窗**，不是产品。
  负向清单明列「完整 GUI」。
- **不做公网暴露**：ADR-072 §10「只绑本地」的精神是「驾驶舱不面向公网」。
  本 ADR 放开的是**受控网络**（VPN / 内网），不是公网。
- **不做 SSE / WebSocket**：ADR-072 §6 已定 —— SSE 要在服务端保持连接状态，
  那是**内存状态**，与 C1 冲突。手机端同样用轮询。
- **不改任何事件类型、不改 schema**：本 ADR 是**纯展示层 + 传输层**改动。
  事件流契约零改动（与 ADR-086 §6 同一条纪律）。

### 后续补齐（落地后实测发现，本 ADR 追加）

上面这套实现**落地后**实测发现一个缺口：决策三的链路是
「人显式 `--host` → 驾驶舱对外可达 → 手机连得上」，
但**最后一步「手机连哪个地址」没有落地** ——
横幅只印 `http://0.0.0.0:4321`，而 `0.0.0.0` 是「绑定到所有网卡」的
**服务端**通配，**手机拨不通**（实测：拨 `0.0.0.0` 连接失败，
拨物理网卡 200）。于是人必须自己知道台式机的局域网 IP 才能连上。

补齐内容（2026-11-28）：

| 文件 | 改什么 |
|---|---|
| `src/cli/commands/web-dialable.ts` | **新增**：枚举本机**物理网卡**地址 + 渲染成横幅行。物理/虚拟用**系统权威判据**（Windows `Get-NetAdapter.Virtual` / Linux `/sys/class/net/<if>/device` / macOS `networksetup -listallhardwareports`），**不按名字猜** |
| `src/cli/commands/web.ts` | 绑定面放开时，额外打印「📱 手机上打开」与可拨地址清单 |
| `tests/web-dialable-addresses.test.ts` | **新增**（20 个用例） |

**为什么物理/虚拟不按名字猜**：名字是厂商自由发挥的 ——
ZeroTier 的虚拟口就叫「ZeroTier One」，不含任何「虚拟」字样；
且 `Win32_NetworkAdapter.PhysicalAdapter` 会把 ZeroTier 误报成 `TRUE`。
只有 `Get-NetAdapter.Virtual` 是权威的。

**为什么只列物理网卡**：手机连同一个 Wi-Fi 只能用到物理网卡那个地址；
VPN 虚拟网卡要走「手机也装同一个 VPN」那条完全不同的路径，
混在一张「连这个就行」的清单里会误导人。

**探测失败时**：如实标「未能确认是否物理网卡」，并用名字关键字**保守排除**
（宁可漏列，也不把虚拟网卡说成物理）。

> **契约零改动**：本补充是**纯展示层**改动 —— 不改 schema、不改事件类型、
> 不改配置格式、不动 `core/`（C2 / C3 / C4 均不受影响）。
> 所以按 AGENTS.md「改动契约才写 ADR」的纪律，**不需要新 ADR** ——
> 它是本 ADR 决策三落地后的收尾，在此处记录以保持追溯链完整。

### 后续补齐之二：移动端交互实测（2026-11-28）

决策四（窄屏适配）落地后，用 Chrome DevTools 在 **390×844** 视口
（iPhone 尺寸）实测，发现**决策四只做了「排版」，没做「可点」与「可键盘用」**。

实测数据：

| 元素 | 实测尺寸 | 问题 |
|---|---|---|
| `.q-option`（提问候选答案） | **57×27px** | 它是「手机回答 agent 提问」时**最常点的元素**，27px 高在手机上点不准 |
| `← 返回` | **42×31px** | 低于 44px 触摸目标下限 |
| `.next-cmd`（待办命令行） | 37px | 同上 |
| `:focus-visible` 规则 | **0 条** | 键盘用户 Tab 过去**不知道自己在哪**（按钮样式盖掉了浏览器默认焦点环） |
| 可点击行 | **154 个，0 个有 `tabindex`/`role`** | 键盘与读屏用户**完全进不去**列表 |
| 窄屏导航 | 占 **3 行** | 首屏内容被挤到屏幕外 |

补齐内容：

| 文件 | 改什么 |
|---|---|
| `src/adapters/web/frontend/styles.css` | 窄屏补 `.q-option` / `.back` / `.next-cmd` / `.answer-row` 触摸目标（全部 ≥44px）；加全局 `:focus-visible` 焦点环；窄屏导航折叠样式 |
| `src/adapters/web/frontend/app.js` | `table()` 给可点行挂 `tabindex="0"` + `role="button"`，Enter/Space 都能触发（Space 带 `preventDefault`）；导航折叠的 JS；`viewSlices` 与 `showSliceDetail` 改为 `Promise.all` 并发取数 |
| `src/adapters/web/frontend.ts` | 导航加 `#nav-toggle` / `#nav-current` / `#nav-list`；**拉闸按钮留在 `#nav-list` 之外** |
| `tests/web-mobile-usability.test.ts` | **新增**（25 个用例） |

三条设计取舍：

1. **为什么用 `:focus-visible` 而不是 `:focus`** —— `:focus` 在鼠标点击时
   也会亮，鼠标用户每点一下都看到一圈高亮，很吵。
   `:focus-visible` 只在键盘导航时亮。
   用 `outline` 而不是 `box-shadow`：不触发布局抖动，
   且 Windows 高对比度模式下会被系统接管（不会被抹掉）。

2. **为什么拉闸按钮要在折叠菜单之外** —— ADR-084 说拉闸是
   「随时可能需要的动作，不该藏在某个视图里」。折叠后如果把它收进菜单，
   等于**藏得更深**了。真出事时要能一眼看到、一键点到。

3. **为什么桌面端一像素不变** —— 折叠按钮在 ≥721px 时 `display:none`，
   `#nav-list` 是普通 flex 排布，与改动前完全一致。
   驾驶舱的主场景仍是桌面（agent 跑在台式机上），
   不该为手机端牺牲任何桌面体验。

> **契约零改动**：与上一节同理 —— 纯前端展示与交互层改动，
> 不改 schema / 事件类型 / 配置格式，不动 `core/`（C2 / C3 / C4 不受影响），
> **不需要新 ADR**，在此记录以保持追溯链完整。

## 不变量核查

- **C1**（状态只在文件里）：**无影响** —— 改动全在传输层与展示层。
  轮询读文件，天然与 CLI 一致（ADR-072 §6 的理由）。
- **C2**（`core/` 零第三方依赖、不 import `adapters/`）：**无影响** ——
  `core/` **一行都不改**；新增代码只用 Node 内置（`node:url` 的 `URL` 解析 Origin）。
- **C3**（判定确定性）：**加强** —— Origin 校验是**传输层的请求准入判定**，
  不是业务判定。它读请求头、不调模型、不触网，仍然是纯计算。
  业务判定（签字四项确认、门禁、冻结）**一行都不改**。
- **C4**（append-only 事件流）：**无影响** —— 契约零改动。
  窄屏适配不改变「谁在什么时候做了什么」。
- **C5**（保护域与锚点外部化）：**无影响** —— 本 ADR 不碰保护域、不碰 policy。
- **C7**（llm 只产草稿）：**无影响**。
- **C9**（写集预约运行时强制）：**无影响** ——
  `run` 仍由 CLI 子进程执行，运行时守卫与写后审计**原样复用**（ADR-086 §7）。

## 验收标准

1. ✅ `zelto web` **默认仍只绑 `127.0.0.1`**（行为不变）；
2. ✅ `zelto web --host 0.0.0.0` 能绑到非回环，且**启动时打印警示横幅**，
   横幅里说清「同网设备能拿到 token 并替你签字」；
3. ✅ `--host` 给了非法值（空串 / 非 IP / 负数 / 端口 > 65535）→ **明确报错退出**，
   不静默回退到回环（与 `parsePort` 同一条纪律）；
4. ✅ Origin 为 `http://<Host头>` 同源形态 → 写操作**放行**；
5. ✅ Origin 与 Host 头**不一致** → 写操作**被拒（403）**；
6. ✅ Origin **存在但解析不出来** → **被拒（403）**，不许当空 Origin 放行；
7. ✅ Origin 为空（curl / 脚本）→ 放行（既有行为不变）；
8. ✅ **CORS 头依然一个都不发** —— 跨源读仍然被堵（ADR-072 §3 不变）；
9. ✅ 窄屏（≤720px）下：表格变卡片、列名可见、导航不横向溢出、
   按钮触摸目标 ≥44px；
10. ✅ **桌面端排版不受影响**（断点之外零变化）；
11. ✅ `npm test` 全绿。

## 已知取舍（明确记录，不假装没有）

### 1. 信任网络隔离 = 放弃了一层防护

人明确选择了「信任网络隔离，不强制访问密钥」。本 ADR 记录这个取舍：

- **同网段任何设备**都能 `GET /` 读到会话 token，然后替人签字 / 拉闸 / 开跑。
- **驾驶舱持有项目目录写权限**，能起 agent（烧 token）。
- 缓解手段只有一条：**必须显式 `--host`**，且**默认关**。

若将来要收回这个取舍，最小改动是加 `--host <非回环>` 时**强制要求**一个
`--access-key`（或从环境变量读），否则拒绝启动 —— 决策二的第 3 点留了位置。

### 2. 「重启切片」依赖台式机本身在线

agent 跑在台式机上。台式机**合盖睡眠 / 关机 / 断网**时，
手机点「开跑」会失败（连不上驾驶舱）或起了跑不动（agent 依赖本机环境）。

**这不是 zelto 能解决的** —— 需要的是机器常醒 + 远程唤醒（WOL）。
本 ADR 不管这件事，但**必须说清楚**，否则人会以为「做了手机端就等于远程可控」。

### 3. 手机浏览器标签页的生命周期

手机浏览器会**冻结后台标签页**（iOS Safari 尤其激进），
5 秒轮询会停。回到前台时前端会恢复轮询（现有 `setInterval` 逻辑），
但**冻结期间人看不到任何更新** —— 界面显示的是上次渲染的画面。

**不为此加 SSE**（决策五，理由同 ADR-072 §6）。但前端**已有**连接状态条
（`#conn`），断连会变红并写明「已停止刷新」（ADR-072 §6.2）——
冻结不等于断连，所以冻结时**不会**变红。这个局限**接受**。

## 被否决的选项

### A 方案：做独立手机 App / PWA

**否决理由**：驾驶舱是**开发工具的观察窗**，不是产品。
要付出的代价（打包、发布、版本兼容、离线缓存）是「窄屏 CSS + 一次 Origin 修正」的百倍。
且负向清单明列「完整 GUI」。

### B 方案：不做窄屏，只解决网络可达性

**否决理由**：窄屏下 9 列的表格挤成一团，「能连上但看不清」等于没做。
CSS 断点的成本很低（一个 `@media` 段），不做是纯粹的省事不省事。

### C 方案：Origin 校验改成「白名单 origin 列表」

**否决理由**：白名单需要人**配置**，且配错就**静默失灵**（403 全灭，人查不出原因）。
而 `Origin` vs `Host` 是**浏览器同源策略自己的定义** —— 零配置、零维护、
且在「换个地址访问」时自动正确。

### D 方案：强制访问密钥（决策二的另一种做法）

**否决理由**：人明确选择信任网络隔离。
且强制密钥会引入「密钥怎么分发到手机上」的问题 ——
那需要另一套机制（配对码 / 二维码），成本远大于本 ADR 的全部改动。
**该选项在决策二 §3 留了位置**，将来要收回取舍时启用。
