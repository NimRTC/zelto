# ADR-116：ADR 每号只有一个家，家之外的文件必须与家一致

**状态**：实施
**日期**：2026-11-26
**相关**：ADR-102 / ADR-103 / ADR-104（版本追溯三件套）、ADR-110（发布锚点）、ADR-113（`ADR_PREFIXES` 契约面变更纪律）、C2、C3、C4

## 背景

ADR 文档现在分两处存：

| 位置 | 份数 | 说明 |
|---|---|---|
| `docs/adr-<num>-<slug>.md`（扁平） | 65 | ADR-010 … ADR-108，以及 102/103/104 的**旧副本** |
| `docs/adr/adr-<num>-<slug>.md`（目录） | 47 | ADR-057 … ADR-115，以及 102/103/104 的**正式版** |

030 之后的写法是目录式；030 之前的扁平文档**没有搬家**（有 40 多份被各切片、验收测试、发布预检按原路径引用），这个分居状态本身可以接受 —— 可接受的前提是**每个编号只在一处**。

2026-11-26 实测，同一编号出现在两处的不止清单上的三份：

1. **102/103/104 三份**：目录版是超集，正文逐字相同，比扁平版多一个「版本追溯」小节；追溯脚本扫的是目录版。于是扁平版是一份**缺章节的影子**。
2. **047 两份是不同的决定**：`adr-047-agent-failure-unsticks-slice.md`（agent 失败要解开切片，扁平）与 `adr-047-submodule-pointer-alignment.md`（submodule 对齐指针，扁平）。前者被 ADR-052 / ADR-053 / 文档索引按 047 引用；后者只在 worktree 相关代码里被引用。
3. **057 两份也是不同的决定**：`docs/adr/adr-057-abandoned-slice-does-not-block-version-delivery.md`（目录，被 `ai-pipeline.ts` 的实现注册按 057 引用）与扁平 `adr-057-spec-conformance-and-glossary.md`（`zelto spec-check` / `zelto glossary` 的出处，被 `events/stream.ts` 与项目目标文档按 057 引用）。

还有一批**指向不存在文件的路径引用**（幽灵路径）。手写一个「看似合理」的路径就造出了一条断链，没人会发现。例如本地曾冒出一个从未入库的 `adr-047-submodule-align-to-main-repo` 文件，正是被这类引用「召唤」出来的。

## 决策

### 决策一：一个编号只能对应**一个决定**

- 102/103/104：目录版是家，扁平侧的逐字影子删除（删前逐字核对：仅多出「版本追溯」小节，不丢信息）。
- 047：两份是**不同决定**，不能当副本处理。以被引用最多的那份（agent 失败解开切片）保留 047；另一份（submodule 对齐指针）改号为 **ADR-117**。
- 057：同理，「放弃的切片不阻塞交付」保留 057（被代码注册按号引用）；「规格符合性检查与领域词汇表」改号为 **ADR-118**。
- 改号的文件保留一行「原编号 ADR-0xx」的说明；引用它们的地方按内容（而非按号）迁移 —— 不批量替换 `ADR-047` / `ADR-057` 的字样，那会把一个原本就混指两份的编号彻底搅乱。

### 决策二：非家位置的文件必须与家**逐字一致**

某些切片因为历史引用需要保留副本时，副本必须逐字等于家。任何一个新出现的复印件、副本漂移，都要在 `scripts/adr-trace-check.mjs` 里当场判非零。

### 决策三：引用必须指向版本库里真实存在的文件

`docs/` 下任何 `.md` 里 `docs/…adr….md` 形式的路径引用，必须命中 `git ls-files`。按版本库判定（不是按工作区 `existsSync`）—— 一次上位数：本地幽灵文件与真正的断链都会被抓住。

本次落地时修掉的断链：
- 两份「已移入目录」的 ADR（070、072）按真实文件名改回扁平路径；对它们写错的目录内路径一并改回
- 044、090 的短名改回真实文件名（扁平 044 与目录 090）
- 047 的失效路径改指真实的 ADR-117
- 028 / 035 的「举例」写法改成不会被判定的形式
- 056 指向了不存在的目录内路径，改回真实的扁平文件

### 决策四：不用「同步文档」代替「删副本」

影子副本的存在本身会诱使后来的人去修补它 —— 每次修复都要记得改两处。所以优先删除；只有确实有技术需要时才用「逐字副本 + 一致性检查」这条兜底。

## 被否决的方案

1. **把扁平 65 份全部搬进 `docs/adr/`** —— 会打断多个切片、验受测试、`build.mjs` 预检与既有文档里的路径引用；搬迁与「同号两处」不是同一个问题。
2. **把 102/103/104 的目录版改成扁平版** —— 与追溯脚本的扫描目录、`adr-trace-index.md` 的登记口径都不一致。
3. **只加 CI 检查不删副本** —— 一个「已收容的违规」在 CI 里是黄的、在读者眼里是红的；先清干净，检查才守得住零。

## 后果

- `scripts/adr-trace-check.mjs` 新增两道判据（同号两处存在 / 副本漂移 / dangling 引用），任一命中退出码非零 —— 该脚本是 `build.mjs` 发布预检的「ADR 追溯检查」阶段，因此**发布闸门**自动带上新判据；
- `ADR_PREFIXES` **不动**（ADR-113：契约面变更需另立决定）；新判据不依赖它的清单，扫全量 `docs/adr/` 与 `docs/adr-*.md`；
- `v2-adr-trace` 验收测试原来读扁平路径，本 ADR 落地时补成「两个位置读同一份内容」的契约：将来任何副本漂移都会让两份读出来的正文不一致。
