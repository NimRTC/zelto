# ADR-119：git hook 对「没有规则匹配」只告警，对「判定没跑成」必须拦截

**状态**：实施
**日期**：2026-11-26
**相关**：C5（保护域不可被覆盖）、C9（写集预约运行时强制，缺失 fail closed）、ADR-014（运行时策略强制）、ADR-054（托管规格豁免在兜底档）

> 编号说明：落地初稿用了 ADR-116（已被同日「ADR 单家」决定占用），
> 并入时改号为 119。

## 背景

生成的 git hook（`src/cli/commands/hook-install.ts` 的 `hookScript()`）在提交时刻对每个改动文件跑一次 `zelto-hook` 判定，然后按 `decision` / `matched_rule` 分档：

| `decision` | `matched_rule` | 当前行为 |
|---|---|---|
| `deny` | 某条显式规则（如保护域） | **拦截** |
| `deny` | `default`（「没有规则匹配」） | 告警放行 |
| `deny` | `null`（判进程出错：二进制缺失 / 崩溃 / 空输入） | **放行** ← 缺陷 |
| 其它（`allow` / `ask` / 空输出） | — | 放行 |

第二行是**有意的**，代码注释也写着理由：「策略没覆盖到的文件会把整条提交堵死，钩子反而变成摆设」。这条判断是否成立需要一份书面决定 —— 本 ADR 给出它。

第三行是**缺陷**：`zelto-hook` 起不来时脚本手里没有任何结论，却和「没有规则匹配」走了同一条放行分支。这正是 `tests/hook/hook-script.test.ts` 里那条实测过的坑：

> hook 脚本把 stderr 丢进 `/dev/null` —— 判定结果为空…… **静默放行**。
> 一个静默失败的守卫比没有守卫更糟：它让人以为门禁在。

## 决策

### 决策一：git hook 层，`default deny` 降级为告警 —— 有边界地保留

**为什么可以降级**：git hook 不是保护域的第一道门。C5 的保护域拦截发生在 `zelto-hook` 判定内部并按**显式规则**命中；「没有规则匹配」只说明策略没有覆盖到这个路径，不说明发生了越界。把「策略没覆盖」当成越界处理，等价于要求 `policy.yaml` 覆盖仓库里的每一个文件，这既做不到也不是策略的意图（`policy/policy.yaml` 的 allow 规则覆盖写集，而项目里的文档、测试夹具、构建产物并不总有对应规则）。

**边界**：
- 降级只发生在 **`git-human` 的提交时刻**——保护域防的是 agent；agent 环路由 PreToolUse（`zelto-hook pretool`）逐写判定，那里**不降级**（C9）；
- 降级只把 `default deny` 从「拦截」挪到「告警」——**告警必须可见**（每次提交在 stdout 打印一行），不能静默丢；
- **不在本 ADR 里**改动 PreToolUse 路径的同名判定。`pretool.ts` 的 `default deny` 是否也应 fail closed，需另立决定。

### 决策二：`matched_rule` 为 `null` —— 必须拦截（C9）

判定进程没有给出可解释结论（二进制缺失、崩溃、输出为空或非法 JSON）时，hook 脚本**不得**把该文件当「通过」——
- `matched_rule` 缺失或为 `null` → `HAS_DENY=1`，提交被拦；
- 二进制找不到时脚本自身的 `exit 0` 改为 `exit 1`，并明示怎么跳过（`git commit --no-verify`）；
- 「拦截」只加在判定**没有结论**的情形；`allow` / `ask` 的行为不变（`ask` 在提交时刻不作为拦截条件，与既有行为一致）。

### 决策三：注释不算背书，ADR 也不算补丁的终点

本 ADR 落地前，第二行的行为在代码注释里有解释但没有 ADR；第四行则是纯粹的缺陷（守卫失效却和「没覆盖」走了同一条放行）。本 ADR 把前者的口径写成决定，把后者修成拦截。

## 后果

- 判定进程坏掉时提交会被拦 —— **会有人第一次遇到**，报错里必须写清怎么绕过；这是有意的成本，因为「守卫坏了但假装在」是更贵的成本；
- 告警行会出现在任何触及未覆盖路径的人类提交上 —— 若噪音过多，正确的解法是在 `policy.yaml` 补规则，而不是删掉告警；
- `tests/hook/hook-script.test.ts` 新增两条断言锁住「default 放行 / null 拦截 / 二进制缺失 exit 1」。
