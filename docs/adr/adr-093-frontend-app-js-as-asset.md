# ADR-093：前端脚本改为独立源文件 —— 不再用模板字符串写 JavaScript

**状态**：已实现（2026-11-19）
**日期**：2026-11-19
**相关**：ADR-072（Web 驾驶舱）、ADR-084（驾驶舱可接管）、ADR-086（驾驶舱油门）、ADR-092（无人值守信任债）
**关联约束**：C1、C2、C4、C5

---

## 1. 摘要

`src/adapters/web/frontend-assets.ts` 目前用**外层模板字符串**承载整个前端脚本
（`renderAppJs()`，约 46KB）。这个结构有一个反复把人绊倒的特性：
**模板字符串会先求值一次**，于是「我写下的字符」与「浏览器收到的字符」不是同一串。

2026-11-19 它已经真实地让整个驾驶舱不可用了一次（见 §3）。本 ADR 提议把它
改成**独立的 `.js` 源文件**，由构建期或运行时嵌入 —— 也就是
**让前端代码作为代码被解析，而不是作为字符串被拼接**。

---

## 2. 问题的本质：两层转义叠在同一个位置

```
源码 (TS)  ──►  外层模板字符串求值  ──►  内层 JS 源码  ──►  浏览器解析
                 ↑ 第一层："我写的" 与 "字符串里的" 在此分叉
```

内层 JS 里一个 `'\n'`，写在模板字符串里会被**外层**先吃掉，变成真换行；
于是**内层**那个字符串字面量跨了行 —— 浏览器看到的是语法错误。

同理，内层注释里一个反引号会**提前终止外层模板**，后面的中文注释被当成代码解析。

两层的转义规则还**不一样**（模板字符串认 `\n`、`\`、`${`，普通字符串认 `\'`、`\"`），
所以「该写一个还是两个反斜杠」永远要靠猜。这不是粗心问题，是结构问题。

---

## 3. 已经发生的故障（实证）

2026-11-19 修复 `e8e2f26` 记录：

| 故障 | 根因 | 症状 |
|---|---|---|
| 整个驾驶舱停在「加载中…」 | `doResume` 的 `confirm` 文案写 `'\n\n'`，外层模板把它求值成真换行，内层字符串跨行 | 45KB 脚本整段被浏览器拒绝；**无任何错误提示**，看上去像「服务连不上」或「轮询卡住」，实际一行没跑 |
| 注释导致 `TS1005 / TS1443` | 新加注释里出现反引号，提前终止外层模板 | 编译失败，报错位置在几百行之后，指不到真凶 |

**为什么测试没抓到**：2602 个测试全绿、lint 全绿、编码检查全绿。
因为**没有一条测试把「浏览器真正会解析的那串字符」交给解析器**。

这一条已经补上（`tests/web-frontend-syntax.test.ts`，5 条）。但那只是**兜底** ——
它让故障变红，却没有让故障**不可能发生**。本 ADR 要做的是后者。

---

## 4. 决策

### 4.1 前端脚本改为独立文件

```
src/adapters/web/
  frontend/
    app.js          ← 浏览器脚本，普通 .js，IDE 直接当 JS 解析
    styles.css      ← 样式表，普通 .css
  frontend-assets.ts  ← 只负责「读取并嵌入」，不再承载代码
```

`frontend-assets.ts` 退化为一个薄层：

```ts
export function renderAppJs(): string {
  return readFileSync(join(__dirname, 'frontend', 'app.js'), 'utf-8');
}
```

**为什么用「构建期/运行时读文件」而不是「构建时把 .js 内联成 .ts 常量」**：

- 读文件最直白，`app.js` 在 IDE 里就是 JS，语法错误当场标红；
- 不需要额外的代码生成步骤（生成步骤本身会变成新的「两级真相」）；
- 独立文件可以直接被 `node --check` / `new Function` 校验。

### 4.2 嵌入方式与「服务端不读任意文件」的边界

ADR-072 §7 的路径穿越防线要求**服务端不读任意文件**。这里读的是
**包内固定的相对路径**，且路径由代码写死（不接受任何外部输入），
等价于现在读一个常量。**防线不变**：

- 路径在 `frontend-assets.ts` 内硬编码，不来自配置 / 请求 / 环境变量；
- 只读 `__dirname/frontend/` 下的两个固定文件名；
- 不使用用户可控的拼路径（与 C5「保护域不可被配置覆盖」同一思路）。

实现时**必须**加一条断言：读不到文件就**显式抛错**，不许静默返回空字符串 ——
空脚本会让页面永远白屏且没有任何提示，那正是本次故障的另一种形态。

### 4.3 构建产物

`app.js` 与 `styles.css` 作为**静态资源**随包发布（`dist/adapters/web/frontend/`）。
`build.mjs` 需要把它们从 `src/` 复制过去；`package.json` 的 `files` 字段需包含它们。

### 4.4 保留 `tests/web-frontend-syntax.test.ts`

新结构下这个测试**仍有价值**（它验的是「最终发给浏览器的那串字符」），
而且会变得更简单：可以直接对 `app.js` 文件本身跑 `new Function`，
不必再从模板里剥出来。

---

## 5. 不做的

- **不引入前端构建工具**（esbuild / vite / tsc 编 JS）：ADR-072 的「无框架、无构建步骤」
  是针对**应用架构**的（不引入框架、不做打包），不是「不许有一个独立源文件」。
  为两个文件引入工具链，收益远小于维护成本。
- **不改成 JSX / TypeScript 前端**：那会把「浏览器不认识 TS」这个问题重新引入一遍。
- **不用 `String.raw` 作为最终方案**：它能缓解 `\n`，但**不能缓解反引号**，
  且仍然保留「内层是字符串」的本质。作为过渡手段可以，作为终态不行。
- **不改动前端行为**：本 ADR 是纯结构迁移，鼠标点下去的效果一行都不许变。

## 6. 影响面

| 文件 | 改动 |
|---|---|
| `src/adapters/web/frontend/app.js` | **新增**：从模板字符串原样迁出（约 46KB） |
| `src/adapters/web/frontend/styles.css` | **新增**：从 `renderStyles()` 迁出 |
| `src/adapters/web/frontend-assets.ts` | 改为读文件；删除两个大模板 |
| `scripts/build.mjs` | 复制静态资源到 `dist/` |
| `package.json` | `files` 增加资源目录 |
| `tests/web-frontend-syntax.test.ts` | 改为直接校验文件 |
| `scripts/build-dist.mjs` | 新增 `copyAssets()`（dist 与 dist-test 共用） |
| `scripts/test.mjs` | 编译 `dist-test` 后复制资源 |
| `scripts/copy-test-assets.mjs` | **新增**：给 `test:unit` 用（它不经 `test.mjs`） |

**不涉及**：`core/`（C2 不受影响）、schema、事件类型、任何判定路径。

## 7. 不变量自查

- **C1**：状态只在文件里 —— 静态资源是**包内容**，不是运行时状态 ✓
- **C2**：`core/` 零第三方依赖、不 import `adapters/` —— 改动全在 `adapters/web/` ✓
- **C3**：判定不触网、确定性 —— 前端是展示层，不参与判定 ✓
- **C4**：每个动作写 append-only 事件 —— 本改动不产生动作，事件流不变 ✓
- **C5**：保护域与锚点外部化 —— 读文件路径写死，不可被配置覆盖 ✓

## 8. 备选方案

| 方案 | 为什么不选 |
|---|---|
| 维持现状 + 只靠语法测试兜底 | 测试只能让故障**变红**，不能让故障**不可能发生**。今天已经因此挂过一次整页 |
| 改用 `String.raw` | 缓解 `\n`，但不解决反引号；本质仍是「代码藏在字符串里」 |
| 引入 esbuild 打包成单文件 | 为两个文件引入依赖与构建链，违背「无构建步骤」的初衷，维护成本高于收益 |
| 用 `<script src="/app.js">` 而非内嵌 | 可行，但需要服务端新增一条静态路由；**可以作为后续优化**，本次先保持内嵌形态以减少改动面（见 §9） |

---

## 9. 未决

1. **内嵌还是外链**：**已定：内嵌**。保持现有 HTML 形态、不动路由与 CSRF 边界，
   只把「字符串来源」从模板换成文件。是否改成 `<script src>` 留给后续单独决定 ——
   那会引入「静态资源要不要也走 token / Origin 校验」的新问题。
2. **迁出时是否顺手整理**：**已定：不整理**。46KB 一次性搬迁，逐字原样搬，
   搬迁提交里没有任何「顺手改一下」。零行为变化用**断言**证明
   （新旧 `renderAppJs()` 输出字符串相等），不靠肉眼看 diff。
3. **是否需要给 `app.js` 加 lint**：**实测结论与最初推断相反** ——
   `biome check src/` **不会检查 `.js` 文件**。用一个明显违规的探针文件验证过：
   `biome check src/adapters/web/frontend/.tmp-probe.js` 退出码 0、零输出。

   所以迁移后前端脚本**仍然没有 lint**（与迁移前一样，只是形态从「字符串」变成「文件」）。
   要不要补是**独立决定**，本 ADR 不覆盖：

   - 补的话需要 `biome.json` 里显式配置 JS 规则，并处理浏览器全局（`window`、`document`）；
   - 但 **`node --check` 已经覆盖了「语法是否合法」** 这一条 ——
     而语法正是今天真正出事的地方，lint 风格问题从没出过事。

   建议：本次迁移**不引入 lint**，保持「零行为变化」的纯度；后续需要时单独一个提交。

---

## 10. 验收标准

迁移完成后，以下每一条都必须成立：

1. **零行为变化**：新旧 `renderAppJs()` 的输出**字符串相等**（用断言判，不靠肉眼看）。
   搬迁提交里**不许混入任何「顺手改」**。
2. `node --check src/adapters/web/frontend/app.js` 通过。
3. `npm run lint`（biome）通过。
4. `tests/web-frontend-syntax.test.ts` 5 条全绿。
5. **重启服务后，先确认监听端口的 PID 就是刚起的那个进程**。
   2026-11-19 的排查中，多次「改了没生效」的真相是旧进程仍占着端口、
   新进程起来就退了。这不是代码要求，是**验证方法**要求：
   没确认 PID 之前，「页面还是老样子」这个观察不能作为任何结论的依据。
6. 用真实浏览器打开，逐页签（总览 / 切片 / 待签字 / 事件 / 度量 / 停机 / 全链 /
   预算 / 策略 / 详情页）确认渲染正常、无 `[object …]`。

## 11. 实施记录（2026-11-19）

### 结果

- `app.js` 46256 字符、`styles.css` 6113 字符，与迁移前基线的**逐字相同**（断言验证）。
- `node --check dist/adapters/web/frontend/app.js` 通过。
- `tests/web-frontend-syntax.test.ts` **7 条全绿**（比迁移前多 2 条：
  「嵌入结果必须与文件逐字相同」×2）。

### ADR 里没预见到的一件事：`dist-test/` 也需要资源

单元测试跑的是 `dist-test/src/adapters/web/frontend-assets.js`，
`readAsset()` 会去它旁边找 `frontend/app.js` —— 但 `tsc` **不复制非 TS 文件**，
于是测试里一调 `renderAppJs()` 就抛「前端资源缺失」。

这其实是好事：**那条显式抛错按设计生效了**。如果当初写成「读不到就返回空串」，
这里会变成「测试全绿但断言的是空字符串」，而生产环境白屏 —— 又一次同样的病。

修法：`copyAssets(root, outDir, outPrefix)` 三个参数。`tsconfig.test.json` 的
`rootDir` 是 `.`，所以 `dist-test` 要多一层 `src/` 前缀；
`tsconfig.json` 的 `rootDir` 是 `src`，`dist` 不需要。这个差异**不能猜**，
必须由调用方显式说出。

### 迁移时踩到的两个坑（都属于「同一类问题还没绝迹」）

1. **模板原文是按 CRLF 读的。** `core.autocrlf=true` 让检出文件是 CRLF，
   `split('\n')` 之后每行末尾残留 `\r`，拼回来与原文件不一致。
   迁移脚本必须先 `replace(/\r\n/g, '\n')` 再拆行。
2. **模板字符串会吃掉紧跟反引号的第一个换行。** 所以 `return \`` 之后的换行
   **不在**内容里 —— 而文件要逐字补回首尾各一个 `\n` 才能与真实输出相同。
   这也是「两层转义」的又一个面：连换行算不算内容都要查规范。

### 遗留

- `dev`（`tsc --watch`）**不会**复制资源。用 `dev` 时前端资源会滞后于源码。
  不在本次范围内 —— 它本来就是交互式 watch，加一步手工复制反而更难用。
  需要时把 `node scripts/copy-test-assets.mjs` 手动跑一次即可。
- 前端脚本**仍然没有 lint**（biome 不检查 `.js`，实测确认）。见 §9.3。
