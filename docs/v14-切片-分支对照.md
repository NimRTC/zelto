## 2a. 版本归属错位：计划说 v1，分支说 v3（ZD-046 / ADR-121）

> 2026-11-26 核对时发现。**这不是「代码丢了」，是「归属记错了」。**
> 机制已修（ADR-121），历史不重写（fix-forward 决策）。本节记录实情。

### 三方对不上的地方

| 说法 | 内容 | 真不真 |
|---|---|---|
| **计划**（`.zelto/versions/plan-1795166129234.json`） | v1 有 10 个切片 | ✅ 真 |
| **事件流**（`.zelto/version-worktrees/v3/.zelto/events/`） | 12 个切片 `merge.completed` 记 `target=main` | ❌ 记错了 |
| **分支事实**（`git merge-base --is-ancestor`） | 那 12 个切片**全在 `version/v3` 上**，`origin/main` 上一个都没有 | ✅ 真 |

**主干没有被污染。** 这是最重要的一条 —— 落点是对的。

### 7 个「计划说 v1、实际在 v3」的切片

`version/v1` 分支上**只含 3 个 v1 切片**（`v1-device-policy` / `v1-audio-p2` / `v1-n5-turn-server`），而且**一个 `Merge slice` 提交都没有**（tip 停在 `628df8c9`，`origin/main...version/v1` = ahead 8 / behind 41）。

另 7 个计划里属于 **v1** 的切片，实际落在 **`version/v3`**：

| 切片 | 计划归属 | 实际落点 | 事件记的 `target` |
|---|---|---|---|
| `v1-ice-recovery` | v1 | `version/v3` | `main` ❌ |
| `v1-turn-credentials` | v1 | `version/v3` | `main` ❌ |
| `v1-sdk-sample` | v1 | `version/v3` | `main` ❌ |
| `v1-path-change-report` | v1 | `version/v3` | `main` ❌ |
| `v1-macos-install-proof` | v1 | `version/v3` | `main` ❌ |
| `v1-install-tree-video-deps` | v1 | `version/v3` | `main` ❌ |
| `v1-install-tree-module-closure` | v1 | `version/v3` | `main` ❌ |

外加 5 个计划里属于 **v3** 的切片（`v1-audio-device-engine` / `v1-call-state-surface` / `v1-turn-tls-trust` / `v1-video-render-engine` / `v6-writeset-slice-boundary`）—— 这 5 片**归属是对的**（v3 就是 v3），只是事件标签写成了 `main`。

### 为什么会这样

`resolveSliceOwnership` 的第 2 级「版本计划成员扫描」读的是**当前目录**下的 `.zelto/versions/`。版本工作目录里那个目录**是空的** —— `version start` 建 worktree 时从不复制计划文件进去：

```
$ dir .zelto/version-worktrees/{v1,v2,v3,v4}/.zelto/versions
（四个都是 0 个文件）
```

于是第 2 级落空 → 第 3 级（规格 frontmatter）也没写 `version:` → **第 4 级兜底「合进主干当前分支」生效**。

而兜底解析出的 `kind='main'` 让 `resolveTarget(null)` 取 `dir = process.cwd()` —— 在版本工作目录里那就是**版本分支本身**。所以：**落点碰巧对了，归属记错了。**

### 已修的部分（ADR-121）

1. `version start` 现在把 `.zelto/versions/<plan-id>.json` **复制进版本工作目录** —— 解析能成功；
2. 版本上下文里**解析不出归属就停下**（抛 `UnresolvedOwnershipError`），不再静默兜底 —— 「不知道」不等于「合主干」；
3. 显式 `--target version/<label>` 反查不到计划时**仍然用它** —— 不听指令比瞎猜更坏；
4. 基点解析（ADR-067）同样 fail closed —— 基点错到主干，agent 会在错误的基础上重写代码。

回归测试：`tests/adr-121-version-context-ownership.test.ts`（14 条断言）。

### 没修的部分（fix-forward 决策）

**已投错的 12 个切片不重放。** 重写版本分支历史的风险远大于收益 —— 实情记录在这里，机制已修。

**那 7 片也不搬移。** 正解是「重新按归属合进 `version/v1`」，但 `version/v1` 与 `version/v3` 已分叉 104 个提交，重做合并会撞 spec 冲突。**留作后续决定。**
