# ADR-106：写集里的规格文件不是「托管文件」

状态：已接受
日期：2026-11-24
取代/补充：ADR-046 §「例外」、ADR-014 §3.3

## 背景

zelto 有两件互相打架的事：

1. **ADR-014 §3.3**：worktree 里的**规格副本**是 zelto 自己放进去的托管文件，
   内容被改动就是**篡改** —— 「改了规格副本等于自动改规格（AGENTS.md 禁区）」。
2. **写集**：人批准的边界。规格文件**在写集里**时，zelto 明确告诉 agent
   「You may only modify these paths」，而这条路径就在名单上。

两件事合起来的效果是：**zelto 一边叫 agent 改规格，一边在运行结束时
因为它改了规格而把整轮运行判成篡改。**

### 现场

nimrtc-v14 的 `v1-call-state-surface` 切片（D7，2026-11-24）：

1. 规格（`specs/slices/v1-call-state-surface.md`）在写集里
   —— 与 v1.4 的其它片一样（`zelto create --writes` 时人显式列的）；
2. agent 写了 ADR（`docs/adr/ADR-035-call-state-surface.md`），
   顺手把规格里那行「架构决策在 ADR-035（**Proposed**，待签字）」
   改成「（**Accepted**，本片落地时签字）」；
3. 运行结束，写集审计判 `tampered`：

```
❌ Slice "v1-call-state-surface" 写集越界 —— 未进入 gate。
   - specs/slices/v1-call-state-surface.md（zelto 托管的文件被改动了 —— 门禁可能已被绕过）
```

4. 切片退回 `frozen`，gate 没跑，签字没发。agent 的活**全做完了**
   （状态机、接线、17 个单测、验收文件、ADR、文档、CHANGELOG 都在树上）。

### 缺陷

**「改了规格就是自动改规格」这句话，在规格文件位于写集时不成立。**

理由是这时的规格文件**不是** zelto 的托管副本语义，而是「人批准的、
agent 有权改的工作文件」—— 人把它列进写集，就是说「这片要改它」。
zelto 拦下来的是**真越界**，不是「人批准过的边界」。

而且 ADR-046 已经为**验收目录**确立了正确判据，却**没把它应用到规格文件**：

> 判据是**写集**：写集里有的 → agent 的地盘；没在写集里的 → zelto 的地盘，
> agent 不该动。

验收目录遵守这条，规格文件不遵守 —— **同一个语义，两套判据**。
这是不一致，不是设计。

### 顾虑：豁免会不会变成「自动改规格」的破口

会 —— 如果只豁免、不补校验。所以本 ADR 有**两条**，缺一不可：

- **第 1 条**（放行）：写集里的规格文件不再登记为托管文件；
- **第 2 条**（收口）：改过的规格文件必须**仍然包含冻结时物化的每一条需求**。
  少了任何一条 → 判篡改。

第 2 条是**规格的锚**：冻结时 zelto 已经把「验收标准」的每一条物化进
`slice.trace.requirements`（ADR-032 §3.3）。那是**人批准的出处**。
agent 可以改规格的措辞、改 ADR 状态、改设计说明 —— 但**不能删掉或
改写验收标准本身**。想改验收标准，只能走 `zelto sign --revise` /
重新 freeze（那会重新钉哈希、重新物化追溯，是**人**的动作）。

## 决策

### 1. 写集里的规格文件不登记为托管文件

`zeltoOwnedPaths()` 的判据与验收目录**统一**：

```
写集里有 → agent 的地盘（不托管）
写集里没有 → zelto 的地盘（托管，内容被改 = 篡改）
```

**注意**：规格文件**不在**写集时，行为一字不变 —— 绝大多数切片
（规格在写集外的那些）仍然受「托管 = 篡改」保护。

### 2. 豁免的条件是「冻结需求仍在」

豁免不是无条件放行。审计时多一道校验：

- 从被改过的规格正文里重新提取需求（`evaluateFreezeTrace` 的同一套提取器）；
- 与 `slice.trace.requirements`（冻结时物化的）逐条比对；
- **少一条**（或某条文本变了）→ 判**篡改**，拦下。

「文本变了」也拦：把「判据 5：X」改成「判据 5：Y」是**改验收标准**，
哪怕条数不变。

**为什么比对文本而不只是条数**：条数不变但内容被换掉，是最常见的
「削弱验收标准」手法。只比条数等于没比。

### 3. 这道校验是**判定**，不是提示

判定发生在写集审计里（`auditWorktreeWrites` 之后），
结果与「托管文件被改」**同档**：拦下、退回 `frozen`、写 `policy.violation`。

不是警告、不是「请人看一眼」—— 因为它拦的正是「自动改验收标准」，
那是要按 AGENTS.md 禁区处理的。

### 4. 判定纯函数、只读、不触网（C3）

需求提取复用 `core/spec/trace-extract.ts` 的现有提取器（纯函数）。
比对是纯计算。不调模型、不发起网络请求。

### 5. 写集判据必须是 C9 的那一个（2026-11-24 补充）

「规格在不在写集里」这个判断，有**两个地方**要做：

1. `zeltoOwnedPaths()` —— 决定规格**要不要被托管**；
2. `buildSpecIntegrity()` —— 决定**要不要给锚**（§2 的「冻结需求仍在」靠它）。

这两个地方**都必须用 `core/sched/paths.ts` 的 `pathInWriteSet`**，
不能自己写严格相等。

**为什么**（本 ADR 落地后的实测缺陷）：

初版两处都用 `writeSet.has(specPath)`（严格相等），而 C9 运行时守卫用的是
`pathInWriteSet` —— 后者认 **glob**（`specs/slices/*.md`）与**目录前缀**
（`specs/`、`specs/slices/`、`specs`），严格相等**不认**。

于是人用这四种写法把规格放进写集时：

| 写集写法 | C9 说在写集里 | 初版说在写集里 |
|---|---|---|
| `specs/slices/v1-x.md` | 是 | 是 |
| `specs/slices/*.md` | 是 | **否** |
| `specs/` | 是 | **否** |
| `specs` | 是 | **否** |
| `specs/slices/` | 是 | **否** |

**分歧的后果是两种坏结果之一，取决于哪一侧先跑**：

- 托管侧说「不在写集」→ 规格被登记为托管 → agent 一改就判篡改
  → **zelto 一边让 agent 改、一边因它改而拦下** ——
  这正是本 ADR 要修的那个矛盾，只是换了种写法没修掉。
- 锚侧说「不在写集」→ **不给锚** → §2 的「冻结需求仍在」**这道校验不生效**
  → agent 删掉验收标准也拦不住 → **漏**。

也就是说：只修一侧，等于把「矛盾」换成了「漏」。**两侧必须同一个判据。**

**顺带修了 ADR-046 的同一个洞**：验收目录豁免原本也用严格相等，
所以 `tests/acceptance/**/*.cjs` 这种 glob 写法同样不生效。

**「同一件事两套判据」是 D-11（合并的两条路径判据不一致）的老教训** ——
判据必须收敛到**一个**实现，不能各写各的。

## 对接点

- 核心：`src/cli/commands/parallel-executor.ts` —— `zeltoOwnedPaths()`
  的规格分支加写集豁免。**判据用 `pathInWriteSet`**（§5）。
- 核心：`src/cli/commands/shared.ts` —— `buildSpecIntegrity()` 产出
  「规格完整性锚」。**判据同样用 `pathInWriteSet`**（§5）。
- 核心：`src/core/sched/audit.ts` —— `auditWorktreeWrites()` 增加
  `specIntegrity` 参数与「冻结需求仍在」的校验。
- 核心：`src/core/sched/paths.ts` —— `pathInWriteSet` 是**唯一的**写集匹配器。
- 核心：`src/core/spec/trace-extract.ts` —— 复用现有提取器，不新增提取逻辑。
- 单测：`tests/d60-detach-managed-paths.test.ts` —— 扩写：写集里的规格
  文件不进托管清单；冻结需求缺失 → 判篡改；冻结需求仍在 → 放行；
  **glob / 目录前缀写集下托管清单与锚都与 C9 一致**（§5）。

## 后果

- **正面**：规格在写集里的切片不再被 zelto 自己的托管规则拦下。
  「人批准的边界」与「zelto 的托管副本」两种语义终于分开。
- **正面**：验收目录与规格文件用**同一条**判据（写集），不再两套。
- **正面**（§5 补充）：托管清单与规格完整性锚**都**与 C9 运行时用同一个
  匹配器 —— 「同一个问题两处判定」不再可能走偏。
- **代价**：规格文件在写集里时，「改它」不再自动判篡改 ——
  所以第 2 条那道校验是**必须**的，不是可选的加固。
- **代价**：多一个参数穿过审计层（`specIntegrity`）——
  审计要知道「冻结时物化了哪些需求」才能比对。
- **不变**：规格文件**不在**写集时的行为完全不变。
- **不变**：ADR-046 对验收目录的豁免**语义**一字不改 ——
  只是把它的判据从严格相等换成 `pathInWriteSet`（§5），
  豁免的口径与 ADR-046 当初的意图一致（写集里 = agent 的地盘）。
