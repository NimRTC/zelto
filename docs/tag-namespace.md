# Git Tag 命名空间（v2-tag-namespace）

治理 Git Tag 命名空间，消除 `v1/v2/v3` 这类裸版本 tag 与计划版本（0.7.x）的歧义。

## 命名规则

- **计划-版本二级命名**：`plan-<semver>/v<n>`，如 `plan-0.7.1/v1`。
  - `<semver>`：计划版本的 semver，形如 `0.7.1`。
  - `<n>`：该计划版本下的版本序号，形如 `1`。
- **裸版本 tag（`v1` / `v2` / `v3`）非法**，须迁移到新命名空间。
- **纯 semver tag（`^v\d+\.\d+\.\d+$`，如 `v0.3.0`、`v0.6.0`）合法**，不受影响、不迁移。

## 存量迁移

存量裸 tag `v1` / `v2` / `v3` 重命名迁移到新命名空间，旧名到新名的映射保留在
`scripts/tag-map.json`（固定为 `{ "<old>": "<new>" }` 扁平映射）：

| 旧名 | 新名 |
|------|------|
| `v1` | `plan-0.7.1/v1` |
| `v2` | `plan-0.7.1/v2` |
| `v3` | `plan-0.7.1/v3` |

迁移只改文档与映射、不自动改 tag；删除远端旧 tag 是人的手动动作。
若 `v1/v2/v3` 已被外部引用，重命名后旧引用会失效 —— 新名在文档与映射中声明，
旧 tag 由人确认后再删。

### 已完成的迁移（2026-11-25）

| 旧名 | 新名 | 指向 | 处置 |
|------|------|------|------|
| `v1` | `plan-0.7.1/v1` | `532f942`（与旧名同一提交） | 旧名已删 |
| `v2` | `plan-0.7.1/v2` | `de3e22c`（与旧名同一提交） | 旧名已删 |
| `v3` | `plan-0.7.1/v3` | `482e0a4`（**与旧名不同**） | 旧名**保留** |

> **`v3` 为什么例外** —— 实测（2026-11-25）：
> 裸 tag `v3`（`636a504`）装的是**另一个计划** `plan-1795422836717`
> 的 v3（v3-docs / v3-help-system / v3-why-command），
> 而 `plan-0.7.1/v3`（`482e0a4`）装的是**本计划** `plan-1795507341754`
> 的 v3（v3-release-gate / v3-cicd-compat）。
> **两者不是同一个版本** —— 裸 `v3` 的内容在 main 上，删掉不会丢代码，
> 但它仍是那个计划的追溯锚点（D6-C：版本 tag 是「这一版整体长什么样」的不可变锚点）。
> 删它会毁掉另一个计划的锚点，故按人批决定**保留**。
>
> 代价：仓库里因此还有一个非法命名的裸 tag `v3`，
> 全量 `node scripts/tag-namespace.mjs`（不传参、读 `git tag`）会因它退出非零。
> 这不是缺陷，是「保留另一个计划的锚点」的已知代价 ——
> **要彻底消掉它，得先决定那个计划的 v3 该迁到哪个 `plan-<semver>/v<n>`。**
>
> 另注：`v1` / `v2` 迁移后各自装的是**另外两个计划**的内容
> （`v1` 是 `plan-1794562105642` 的 v1、`v2` 是 `plan-1795422836717` 的 v2）。
> `plan-0.7.1/v1..v3` 这个命名空间因此**跨了多个计划** ——
> 它表达的是「0.7.x 这一批里的第 n 个版本」，不是「某一个计划的第 n 版」。
> 这与 v2 规格的原始设��一致（裸 tag 被视作同一批历史版本），
> 但**规格当时只校验映射表的形，没核对内容**（见下）。

### 映射表的已知局限

`scripts/tag-map.json` 只被 `scripts/tag-namespace.mjs` 用来校验
**新名的命名合法性**（`^plan-\d+\.\d+\.\d+/v\d+$`）——
**它不校验映射的内容对不对**（旧 tag 与新 tag 是否真的指向同一个版本）。

后果：映射表可以把 `v3` 映射到 `plan-0.7.1/v3` 而两者内容不同，
校验照样通过。**这是 v2 规格留下的口子**（验收标准 2 只断言键存在 + 值合法）。
本次迁移中它就暴露了：裸 `v3` 与 `plan-0.7.1/v3` 指向不同版本，
而映射表对此**一言不发**。


## 校验脚本

`scripts/tag-namespace.mjs` 只做校验（列出非法 tag + 非零退出），不自动改 tag：

```bash
node scripts/tag-namespace.mjs [tag...]
```

- 带参：校验给定的 tag 列表。
- 无参：从 stdin 逐行读 tag；stdin 无输入时读 `git tag`（校验仓库当前状态）。
- 退出码：`0` = 全部合法；`1` = 有非法命名 / 版本号不一致 / `tag-map.json` 不合法。

脚本区分两种错误并分别列出：

- **非法命名**：tag 不符合任何合法形态 —— 裸 `v1` / `v2` / `v3` 落在这里。
- **版本号不一致**：`plan-<semver>/v<n>` 的 `<semver>` 与 `package.json` 当前版本漂移。

## 版本一致性

新 tag `plan-<semver>/v<n>` 的 `<semver>` 应与 `package.json` 的 `version` 一致，
防止 tag 与当前版本漂移。映射表指向计划版本（可能超前于当前发布版本），
因此映射只校验命名合法性；对实际 tag 列表的校验才包含版本一致性检查。
