feat(v3-cicd-compat): 发布流水线适配 v2 的 tag 命名空间 —— 但不削弱发布保护

原草案要修的东西不存在：scripts/build-lock.mjs 只有 acquire/release/withBuildLock
三个导出，管的是 .build-lock/ 目录互斥锁（ADR-080），全文检索 version 命中 0 次。
故改为修实测存在的 CI/CD 不兼容：

- release.yml 的触发条件只有 tags: ['v*']，不匹配 v2 新定的 plan-<semver>/v<n>
- release.yml 内联 v${PKG} 比对版本号，不查命名合法性、不查存量映射
- 仓库里已有唯一判据 scripts/tag-namespace.mjs，流水线却自己手写了一套更弱的判定

**关键：本次是「加一条校验」，不是「换掉原有校验」。**

实测发现 tag-namespace.mjs 按设计不管纯 semver tag 的版本一致性 ——
`node scripts/tag-namespace.mjs v0.6.0` 在 package.json 为 0.7.1 时退出码 0
（checkTag 对 SEMVER_TAG 直接 return null）。它只在命名空间 tag 上校版本。

所以若按原草案「不再内联 v${PKG} 比对」执行，
会**静默削弱**「发出去的包和仓库对不上」那条保护：
打一个 v0.6.0 的 tag 就能把 0.7.1 的包发出去。

现改为两件不同的事、判据不同源：
  ① 命名合法性 → 唯一判据 scripts/tag-namespace.mjs，workflow 只调用不复制规则
  ② 版本号一致性 → 留在 workflow 里（tag-namespace.mjs 不管纯 semver tag）

改动
- .github/workflows/release.yml
  - 触发条件加 plan-*/v*（v* 原样保留，两类触发并存）
  - 校验步骤调用 node scripts/tag-namespace.mjs（显式喂 tag，非交互）
  - 保留并加强版本号比对：两种 tag 形态都取 semver 再与 package.json 比
- specs/slices/v3-cicd-compat.md —— 规格按实测改写
- tests/acceptance/v3-cicd-compat/acceptance.test.cjs —— 8/8

验收测试里三个坑（都踩过，写进注释了）：
- 抽取 shell 时不能用 `#.*$` 就地截断去注释 —— 会把 ${TAG#plan-} 里参数展开的
  # 当注释起点，代码被截成 `TAG_SEMVER="${TAG`，bash 报 unexpected EOF
- 不能单独去掉 `if [ "${GITHUB_REF_TYPE}" = "tag" ]` 外壳 —— 会留下落单的 fi
- 跑 bash 要用「脚本文件 + 位置参数 + 仓库内相对路径」：
  本机 bash 是 WSL 的 bash（x86_64-pc-linux-gnu），既收不到 Windows 侧环境变量，
  对 `bash -c` 的位置参数处理也与 Git Bash / Linux 不一致
