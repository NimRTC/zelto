# Slice: v1-event-hash-chain

## 目的

在现有 `src/core/events/stream.ts` 中扩展事件流能力：为新写入事件追加 `prevHash` 链接、计算并持久化 SHA-256 哈希，提供读取完整事件链和验证哈希链完整性的接口，从而为事件流提供可审计、可校验的哈希链核心能力。本片不引入签名机制与并发锁，也不追溯补齐历史事件的哈希。

## 范围

要改的（这些是 agent 会去改的文件）：
- `src/core/events/stream.ts`

只读参考（**不得修改**，agent 只许读）：
- 无

## 需求

无

## 验收标准

1. 在 `src/core/events/stream.ts` 的 `EventEnvelope` 类型上新增 `prevHash` 字段（类型为 `string | null`）和 `hash` 字段（类型为 `string`）；验证方式：检查该文件中的类型定义，并确认类型检查（如 `tsc`）通过。

2. 实现用于写入新事件并加入哈希链的逻辑：写入时若链中已有前序事件，则将前序事件的 `hash` 赋值给新事件的 `prevHash`；新事件的 `hash` 为对其规范化内容（内容应包含事件自身数据及 `prevHash`）计算得到的 SHA-256 值，并随事件持久化；验证方式：调用该写入逻辑连续写入 3 个事件，检查持久化数据中每个事件的 `hash` 与按同一规范化规则重新计算的 SHA-256 一致，且第 2、3 个事件的 `prevHash` 分别等于第 1、2 个事件的 `hash`，第 1 个事件的 `prevHash` 为 `null`。

3. 实现 `verifyChain` 接口：从链首事件开始逐事件校验哈希与前序链接，返回校验结果（布尔值或包含成功/失败信息的结构）；验证方式：对一条正常写入的事件链调用 `verifyChain` 返回成功；然后人为篡改链中某个事件的 `hash` 或 `prevHash` 字段，再次调用 `verifyChain` 返回失败。

4. 实现 `loadChain` 接口：从持久化存储中读取完整事件链，并按写入顺序返回全部事件；验证方式：写入若干事件后调用 `loadChain`，返回数组中事件数量与写入数量一致，且顺序与写入顺序一致。

## 风险

- 事件内容的规范化规则若不固定，会导致同一事件在不同时间计算出不同哈希，进而破坏链校验；应对：在实现中明确并固定规范化规则（如字段排序、JSON 序列化方式），验收时用同一规则复算校验。
- 对已有事件进行追溯补哈希会超出本片范围，若误实现可能引入与设计不符的行为；应对：实现仅针对新写入事件，不修改已存在事件的哈希。
- 若 `hash` 或 `prevHash` 字段被允许为空字符串或非法值，可能绕过链完整性检查；应对：在写入逻辑中强制生成非空哈希，并在 `verifyChain` 中拒绝空值或不合法值。
- 持久化读写与 `stream.ts` 现有事件存储方式耦合，若假设了不存在的数据形态可能编译失败；应对：实现时以 `src/core/events/stream.ts` 中实际已有的事件存储读写作基础，必要时将存储细节隔离在局部函数内。
