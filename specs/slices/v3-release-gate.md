# Slice: v3-release-gate

## 目的
本切片将 v2 已实现的 Git Tag 命名空间治理、版本一致性检查、ADR 追溯检查和验收测试编排能力，在 `scripts/build.mjs` 中通过 `--release` 入口串联成一个发布前强制预检门禁：预检按固定顺序执行，任一环节失败即中止流程；全部通过后输出 git 命令、ADR 文档、发布清单三种追溯途径，确保交付后可以立即从三条途径核验发布内容与决策。

## 范围

要改的（这些是 agent 会去改的文件）：
- scripts/build.mjs

只读参考（**不得修改**，agent 只许读）：
- 只读 scripts/build-dist.mjs —— 同属发布收口模块，负责发布产物/发布清单的生成；`--release` 预检通过后需要引用其输出位置或发布清单内容来完成追溯信息展示，不得修改。
- 只读 scripts/build-lock.mjs —— 同属发布收口模块，负责版本锁定与一致性校验；预检需要读取它产出的版本锁定信息来判断版本一致性，不得修改。

## 需求
无。

## 验收标准
以下条目为草案：本切片没有关联需求，验收标准依据所属模块的人批设计上下文拟定；在需求补齐并复核前，这些标准不视为最终口径。

1. `scripts/build.mjs` 支持 `--release` 参数且该参数触发发布预检；验证方式：运行 `node scripts/build.mjs --release`，stdout 出现预检阶段标识（如 `[release-gate]`）；运行 `node scripts/build.mjs` 不带 `--release` 时，不出现该标识。
2. 发布预检按固定顺序依次执行 Git Tag 命名空间治理、版本一致性检查、ADR 追溯检查、验收测试编排；验证方式：执行 `node scripts/build.mjs --release`，检查日志中四类阶段标识按上述顺序出现，且每下一步只在上一步成功返回后执行。
3. 预检中任一阶段失败会立即中止流程并产生非零退出码，错误信息包含失败阶段名和失败原因；验证方式：分别制造 tag 命名不规范、版本号不一致、ADR 记录缺失、验收测试失败四类仓库状态，运行 `node scripts/build.mjs --release`，每次都断言退出码非零、错误信息含对应阶段名、后续阶段日志未出现。
4. 预检全部通过时，stdout 同时给出三种追溯途径：git 命令（或 tag 查询命令）、ADR 文档路径、发布清单路径；验证方式：在满足预检条件的仓库成功运行 `node scripts/build.mjs --release`，抓取输出并确认三类信息均存在，且 ADR 文档路径与发布清单路径指向实际存在的文件。
5. 预检未通过时不进入发布产物生成/收口动作；验证方式：在任一预检失败场景下运行 `node scripts/build.mjs --release`，检查发布产物目录或发布清单文件在运行前后无新增、无内容变化。
6. 不带 `--release` 的既有常规构建路径执行方式与 v2 保持一致，不触发上述预检；验证方式：运行 `node scripts/build.mjs`（不带参数），日志中无预检阶段标识，退出码与 v2 基线的同命令一致。

## 风险
- 关联需求为空，验收标准是草案，可能不被验收门禁接受；应对：进入实现前先由需求人补齐需求并复核本规格，确认后再编码。
- 前片 v2 的实现接口可能与本次串联预期不一致（例如检查函数未导出、输出格式不同）；应对：先阅读 v2 改动与 `scripts/build-dist.mjs`、`scripts/build-lock.mjs` 的实际接口，只做调用适配，不重写既有逻辑。
- 预检成功路径需要仓库满足 tag、版本、ADR、测试全部条件，构造完整成功场景较难；应对：用本地临时 tag、最小 ADR 文档和一个确定通过的单测目标搭建可预测场景，同时重点验证失败路径的中止行为。
- `scripts/build-dist.mjs` 和 `scripts/build-lock.mjs` 是只读参考，若误改会被门禁拦截；应对：仅在本切片写集中的 `scripts/build.mjs` 内引用或调用，不触碰这两个文件。
- `--release` 可能被误认为直接发布动作，引入多余发布逻辑导致职责膨胀；应对：本切片只实现为发布前预检门禁，输出“预检通过/失败”结论，不新增超出 v2 已有范围的发布操作。
