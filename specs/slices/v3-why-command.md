# Slice: v3-why-command

## 目的
新增 `zelto why [operationId?]` 子命令，向运维人员解释最近一次操作（或指定操作）的决策依据、触发条件、关联上下文与相关事件；同时将该命令注册进命令目录，确保 CLI 能发现并路由到它。由于当前没有关联需求正文，本片以设计上下文中已批准的 why-command 模块职责为行为边界，最终验收口径待需求方补齐后确认。

## 范围
要改的（这些是 agent 会去改的文件）：
- `src/cli/commands/policy-why.ts` —— 实现 `zelto why [operationId?]` 子命令：解析可选参数、读取操作/决策记录、组织并输出解释内容；文件不存在则新建。
- `src/cli/commands/catalog.ts` —— 在命令目录中注册 `why` 命令，包含命令名、参数说明与路由/处理函数绑定。

只读参考（不得修改，agent 只许读）：
- 只读 `src/core` —— 需要读取操作记录与策略决策记录的既有接口，确定最近操作、指定 operationId、决策依据、触发条件、关联上下文与相关事件的获取方式。
- 只读 `src/cli/output-formatter.ts` —— 读取既有输出格式化约定，保证 `zelto why` 的结构化、可读化输出与相邻命令一致。

## 需求
无（本切片没有关联需求条目，验收口径需人补齐后再确认规格）。

## 验收标准
1. 在关联需求正文补齐前，本切片不把任何未经批准的行为锁定为正式验收项；验证方式：检查“关联需求”为 `[]`，且验收标准未引用任何不存在的需求正文。
2. 关联需求正文补齐后，按正文中的验收口径逐条实现并复核；验证方式：需求方依据补齐后的需求正文逐条验收，并能将每条验收标准追溯到 `src/cli/commands/policy-why.ts` 或 `src/cli/commands/catalog.ts` 的对应改动。
3. 本切片不得改动写集以外的路径；验证方式：对本次改动做 diff 审查，确认只有写集中列出的两个文件发生变化。

## 风险
1. 关联需求正文缺失，验收口径不确定：实现方向可能与最终需求不一致。应对：先只按设计上下文中已批准的 why-command 模块职责落地；需求补齐后立即回填验收标准并复核，必要时调整命令行为。
2. “最近一次操作”的语义不明确或操作记录为空：可能导致取错操作或命令崩溃。应对：读取操作记录列表时按时间/记录序取最后一条；无记录时输出明确引导提示，例如“尚无可用操作，请先执行一次操作”，不输出堆栈。
3. 指定的 operationId 不存在或格式非法：可能产生技术化报错。应对：先校验 operationId 是否存在；不存在时输出面向运维人员的提示，并附带 `zelto why` 的简单用法。
4. catalog 注册遗漏或路由不匹配：命令文件实现了但 CLI 无法发现 `zelto why`。应对：在 `src/cli/commands/catalog.ts` 中登记命令名 `why`、参数 `[operationId?]` 与处理函数绑定，并用一次 `zelto why` 调用验证路由生效。
