# Slice: v2-adr-trace

## 目的

为三批直推 main 的修复（agent 占位符剥离、submodule 离线同步、sign-review 作用域证据）补齐 ADR-102/103/104 的版本追溯记录，并提供一个可自动校验回填完整性的脚本 `scripts/adr-trace-check.mjs`，确保每条 ADR 均包含所属版本、关联提交哈希与验证方式，从机制上防止后续再次出现追溯缺失。同时将追溯结果汇总登记到 `docs/` 下的索引文档，供版本一致性检查模块参考。

## 范围

要改的（这些是 agent 会去改的文件）：
- `docs/adr/adr-102*.md`
- `docs/adr/adr-103*.md`
- `docs/adr/adr-104*.md`
- `docs/*.md`
- `scripts/adr-trace-check.mjs`

只读参考（不得修改，agent 只许读）：
- 只读 `docs/README.md` —— 需仿照该文档的 ADR 索引登记格式，确定各 ADR 的编号、标题与状态列写法，确保追溯结果在索引中能被一致识别
- 只读 `scripts/adr-trace-check.mjs`（若已存在）—— 读取该脚本现有校验约定，确认回填字段命名保持一致；若文件尚不存在则跳过
- 只读 前置切片 v1 的产出物（即已回填至 `docs/adr/adr-102*.md`、`docs/adr/adr-103*.md`、`docs/adr/adr-104*.md` 中的历史记录）—— 需要复用其中已约定的版本号、提交哈希格式与验证方式标记，避免同一字段出现多种写法

## 需求

无（本片没有关联的需求条目，需求正文空缺；验收标准需人补齐后再确认规格）。

## 验收标准

1. 在 `docs/adr/adr-102*.md`、`docs/adr/adr-103*.md`、`docs/adr/adr-104*.md` 三个文件中，每份 ADR 文档均新增或更新「版本追溯」小节，内容至少包含：所属版本号、关联 ADR 编号、提交哈希、验证方式四项字段；验证方式：人工查阅三个文件，确认每个文件都存在上述四项且值非空、格式统一。
2. 三条 ADR 的追溯记录须分别映射到三批修复：ADR-102 对应 agent 占位符剥离、ADR-103 对应 submodule 离线同步、ADR-104 对应 sign-review 作用域证据，不得串记或漏记；验证方式：逐条核对每份 ADR 正文中描述的修复内容与追溯小节中的提交哈希指向的改动一致（提交哈希可通过 `git show --stat <hash>` 抽查确认）。
3. 新增 `scripts/adr-trace-check.mjs` 校验脚本，执行 `node scripts/adr-trace-check.mjs` 后应能扫描上述三个 ADR 文件，并输出每份 ADR 的追溯字段状态；验证方式：运行该脚本，观察输出结果，应能区分“字段齐全”和“字段缺失”两种状态并给出非零退出码（当存在任一缺失字段时退出码非零，全部齐全时退出码为 0）。
4. 校验脚本须校验「所属版本号」符合语义化版本格式（`v` + 数字 + `.` + 数字 + `.` + 数字）、「提交哈希」为 40 位十六进制字符串、「验证方式」非空且以 `[` 开头并包含 `]`；验证方式：人为将某一条 ADR 的版本号改为 `abc`，运行脚本，脚本应以非零退出码报告该行错误；恢复正确值后再运行应通过。
5. 在 `docs/*.md` 中的 ADR 索引登记表或等价汇总清单里，为 ADR-102/103/104 三条记录补充「追溯状态」列或标记，且值须为「已回填」；验证方式：打开 `docs/` 下的索引文档，确认三条 ADR 对应行均有该标记，且标记与校验脚本输出结果一致（脚本通过时标记为「已回填」）。
6. 不修改写集之外的任何文件；验证方式：执行 `git status`，改动文件列表应严格落在写集的 5 条路径之内；对只读参考文件执行 `git diff` 应无输出。

## 风险

- 三个 ADR 文件中可能存在历史遗留的追溯字段命名不一致（如 `commit`、`hash`、`提交`混用），导致校验脚本匹配失败；应对：脚本内对字段做别名归一化，并在前面「只读参考」中明确仿照已有格式，若历史格式彼此冲突则以 v1 切片已采用的格式为准并统一改写。
- ADR 正文中的提交哈希可能指向的是 squash 后的合并提交，而非精确到某个修复的独立提交，导致回填时选择了错误的哈希；应对：脚本只校验哈希格式与存在性，不校验语义；人工核对时以 `git show --stat` 确认哈希能对应到三类修复的代码改动，若无法定位则标记为「需人工复核」而非臆造哈希。
- `docs/*.md` 中可能存在多个候选索引文件，不确定哪个是正式汇总清单；应对：以 `docs/` 下实际存在的 ADR 索引登记表为准，优先在既有的 ADR 列表文件中追加「追溯状态」列，而不新建汇总文件。
- 写集允许改 `docs/*.md`，但若该路径下存在不宜改动的人批准规划文档，改动可能在门禁处被拦下；应对：只改动与 ADR 索引登记直接相关的文档，修改前先 `git log` 查看该文件的最近修改人，若属于只读参考范围则改为在脚本输出中提供索引建议而非直接改文件。
- 校验脚本的退出码逻辑若与现有 CI 或版本一致性检查模块的约定不一致，可能导致门禁误判；应对：脚本默认采用「任一缺失即非零退出码」的保守策略，并在脚本顶部注释中说明退出码约定，便于后续接入时调整。
