# Slice: v1-acceptance-triage

## 目的
为验收测试建立统一、可重复的编排入口（`scripts/test.mjs`），并修复因两次 ship 合入造成的「lint 通过但运行失败」的集成断点——问题集中在 `tests/**/*.test.ts` 与现有 `src/**` 实现的对接层（导入路径、接口参数、异步时序、mock 形状等），最终使验收测试在干净环境中可全量执行、失败可观测、结果可复现。

## 范围
要改的（这些是 agent 会去改的文件）：
- `scripts/test.mjs`
- `tests/**/*.test.ts`

只读参考（**不得修改**，agent 只许读）：
- 只读 `contracts/schemas/**` —— 测试断言需要按其中的 schema 定义核对实际结构
- 只读 `src/cli/**`、`src/adapters/**`、`src/core/**`、`src/hook/**`、`src/llm/**` —— 测试直接调用这些实现模块，需按其真实接口修复/编写测试
- 只读 `syntax/**` —— 测试若涉及语法解析输出，需参照其导出的形状

## 需求
无（本片没有关联需求条目，验收标准以所属设计的模块职责为基准）。

## 验收标准
1. `scripts/test.mjs` 作为验收测试统一入口，能自动发现并执行 `tests/**/*.test.ts` 下全部测试文件；验证方式：从项目根目录运行 `node scripts/test.mjs`，输出中列出的测试文件数量等于 `tests` 目录下 `*.test.ts` 文件数量，且退出码为 0。
2. `scripts/test.mjs` 对失败可观测且正确传播退出码；验证方式：临时在任一测试文件内加入一条必失败断言（如 `expect(1).toBe(2)`）后运行脚本，退出码非零且输出包含失败文件路径、用例名与失败原因；还原改动后再运行，退出码恢复为 0。
3. 现有 `tests/**/*.test.ts` 与只读的 `src/**` 实现真实对接成功，不再出现「lint 通过但运行失败」的集成断点；验证方式：在干净环境（删除 `node_modules` 与构建缓存后按 lockfile 重新安装依赖）中运行 `node scripts/test.mjs`，输出汇总行显示 `failed: 0` 且退出码为 0。
4. 测试结果可重复，脚本不依赖上一次运行的残留状态；验证方式：在干净环境中连续运行两次 `node scripts/test.mjs`，两次汇总中的用例数与失败数完全一致，且 `failed` 均为 0。
5. 本片改动不越过写集边界；验证方式：执行 `git status --porcelain`，列出的改动路径全部位于 `scripts/test.mjs` 与 `tests/**/*.test.ts` 范围内，`contracts/schemas/**`、`src/**`、`syntax/**` 无改动。

## 风险
- 本片没有关联需求条目，验收口径只能依据设计上下文中的模块职责推导；若需求人后续补齐的验收口径与本规格不一致，需先重新校准规格再实现。应对：实现前先与需求人对齐验收标准。
- 集成断点根因可能实际位于只读的 `src/**` 实现中而非测试侧；应对：测试以明确断言形式暴露该失败，不越界修改只读路径，留给后续切片处理。
- 验收测试可能依赖外部服务（如 LLM API、网络），干净环境下会因网络不可用而失败；应对：`scripts/test.mjs` 提供外部依赖的 mock/桩注入机制，并支持对依赖网络的用例显式标注跳过原因，保证离线环境可重复执行。
- Node 版本与 TypeScript 加载方式差异可能导致 `.ts` 测试文件运行失败；应对：`scripts/test.mjs` 内固定测试运行命令、校验 Node 版本，并在加载失败时输出可操作的错误提示。
