fix(cli): zelto set 的数组字段接受 JSON 数组（ZD-022）

数组字段（writes / trace.*）此前只吃逗号分隔，喂 JSON 数组串会静默
产出带方括号的垃圾条目（如 "[src/a/**"）且报告成功 —— 写集里混进这种
条目既覆盖不到真实路径，又让「写集写了什么」说不清；最坏的情况下
本该被拦的越界写会因为写集看起来更大而被放过，全程无任何报错。

根因是判据不一致：同一条 set 命令里的 spec.gateCommands 早就是 JSON
格式（ADR-051），同类字段一个吃 JSON 一个不吃，用户只能靠猜。

现在两种格式都收：JSON 数组（首选）与逗号分隔（历史格式，保持可用）。
以 [ 开头即按 JSON 解析，解析失败直接报错 —— 不兜底回逗号分隔，
兜底会把「JSON 写错了」变成「写集里多了几个奇怪条目」，那是同一个病。

另含前序会话遗留的修复：
- submodule 失败措辞区分「本地缺 commit」与「远程不可达」（修法不同）
- Linux 措辞也识别成「本地缺 commit」（同一故障条件跨平台措辞不同）
- d74 测试的假适配器持有真实句柄，避免事件循环提前空掉
